# საინფორმაციო გვერდები — რა აკლია

ფუტერის ოთხი გვერდი: მიწოდების პირობები (`/delivery`), დაბრუნება და გარანტია
(`/returns`), კონფიდენციალურობა (`/privacy`), ხშირად დასმული კითხვები (`/faq`).
კოდი — `frontend/src/pages/Info/`, ტექსტები — `frontend/src/i18n/ka.json` და
`en.json` (`info.*`).

2026-11-19-დან ტექსტები კანონს მიჰყვება: „მომხმარებლის უფლებების დაცვის
შესახებ“, „ელექტრონული კომერციის შესახებ“, „პერსონალურ მონაცემთა დაცვის
შესახებ“ (`PROJECT.md`, Decision Log 2026-11-19). დაბრუნების კურიერის
წინადადება და გარანტიის ტექსტი ფიქსირებული ტექსტია (თარგმანის
ფაილებში) — `SHOP_FACTS.returnPickup` და `warrantyPeriod` აღარ არსებობს.
2026-11-20-დან გარანტიას თავად მაღაზია იძლევა: მისი ვადა (თვეებში) ერთ
ადგილასაა — `WARRANTY_MONTHS`, `frontend/src/constants/index.js`; ყველა ტექსტი
მას `{{months}}`-ით კითხულობს. დაბრუნების კურიერის ფასები `GET /delivery`-დან
მოდის (`PROJECT.md`, Decision Log 2026-11-20).

ქვემოთ ჩამოთვლილი **საიტზე ახლა არ ჩანს** — არც ცარიელი ადგილით, არც
„მალე“-თი.

## 1. ვინ ვართ

- **გვერდი:** კონფიდენციალურობა — სექცია „ვინ ვართ“ მთლიანად დამალულია,
  სანამ მონაცემი არ ჩაიწერება. მაღაზიის მისამართი საიტზე სხვაგან აღარსად
  ჩანს (არც ფუტერში, არც კონტაქტში, არც შეკვეთის წერილში) — იურიდიული
  მისამართი მხოლოდ აქ გამოჩნდება.
- **მფლობელი აწვდის:** ინდმეწარმის სრულ დასახელებას, პირად ნომერს /
  საიდენტიფიკაციო კოდს, იურიდიულ მისამართს.
- **ჩაწერა:** `frontend/src/constants/index.js`, `SHOP_FACTS`-ში `null`-ის ნაცვლად:
  `legalEntity: { name: 'ი/მ …', idCode: '…', address: '…' },`
- **შენიშვნა:** ვინ ამუშავებს მონაცემებს — ეს არის ის, რისთვისაც ეს გვერდი
  არსებობს; კანონი ამას მოითხოვს. გამოქვეყნებამდე შეავსეთ.

## 2. შეკვეთის სტატუსი სტუმრისთვის

- **გვერდი:** ხშირად დასმული კითხვები — „შეკვეთის სტატუსი სად ვნახო?“. პასუხი
  ახლა მხოლოდ რეგისტრირებულს მიმართავს; სტუმრის ნახევარი ამოღებულია.
- **რატომ:** სტუმარს საიტზე შეკვეთის მოსაძებნი გვერდი არ აქვს. backend-ს აქვს
  `POST /orders/lookup` (შეკვეთის ნომერი + checkout-ზე გაცემული შემთხვევითი
  token), მაგრამ token მხოლოდ იმ ბრაუზერშია, სადაც შეკვეთა გაფორმდა —
  დადასტურების გვერდის საჩვენებლად. სხვა მოწყობილობიდან ან ისტორიის
  გასუფთავების შემდეგ სტუმარი შეკვეთას ვეღარ ნახავს.
- **რა სჭირდება:** ერთ-ერთი —
  - token-ის მიწოდება სტუმრისთვის სხვა გზით (მაგ. ბმული დადასტურების
    წერილში) და შემდეგ წინადადება `frontend/src/pages/Info/Faq.jsx`-ში — ეს
    ფუნქციაა, არა ერთი ხაზი. ფორმა „ნომერი + ტელეფონი“ აღარ გამოდგება:
    ტელეფონი სხვებმაც იციან და lookup მას აღარ იღებს;
  - ან მფლობელის გადაწყვეტილება, რომ სტუმარს ვწერთ „დაგვიკავშირდით შეკვეთის
    ნომრით“ — ეს ერთი ხაზია იმავე ფაილში.
